# Polymarket Data Adapter

Read-only adapter for Polymarket prediction market data.

## Status

**Phase 1.1 — Read-only data ingestion. No trading, no execution.**

## API Endpoints Used

| Endpoint | Method | Description |
|----------|--------|-------------|
| CLOB `/book` | GET | Full order book for a single outcome token |
| CLOB `/books` | POST | Batch order books for multiple tokens (max 500) |
| CLOB `/price` | GET | Best price for a given side (BUY/SELL) |
| CLOB `/midpoint` | GET | Midpoint price (average of best bid/ask) |
| CLOB `/spread` | GET | Bid-ask spread |
| CLOB `/last-trade-price` | GET | Last traded price and side |
| Gamma `/markets/{id}` | GET | Market metadata by ID |
| Gamma `/markets/slug/{slug}` | GET | Market metadata by slug |
| Gamma `/events/{id}` | GET | Event metadata by ID |
| Gamma `/events/slug/{slug}` | GET | Event metadata by slug |

## Architecture

```
Polymarket CLOB/Gamma API
        ↓
PolymarketClient (provider-specific)
        ↓
Raw Polymarket Models (OrderBookSummary, MarketMetadata, etc.)
        ↓
PolymarketNormalizer
        ↓
MarketQuote (canonical, provider-independent)
        ↓
validate_quote() → Dataset
```

## Raw Models

### OrderBookSummary (from CLOB `/book`)
- **market**: Condition ID (hex string) identifying the market
- **asset_id**: Token ID (large integer string) for this outcome
- **timestamp**: Epoch milliseconds as a string (e.g., `"1782753357257"`)
- **hash**: Hash of order book state for change detection
- **bids**: List of bid levels sorted by price ascending (best bid is last)
- **asks**: List of ask levels sorted by price descending (best ask is last)
- **min_order_size**: Minimum order size (decimal string)
- **tick_size**: Minimum price increment (decimal string)
- **neg_risk**: Whether negative risk is enabled
- **last_trade_price**: Last traded price (decimal string)

### OrderBookLevel
- **price**: Decimal string representation (e.g., `"0.45"`)
- **size**: Decimal string representation (e.g., `"100"`)

### MarketMetadata (from Gamma API)
- **id**: Market ID (numeric string)
- **slug**: URL-friendly market identifier
- **question**: Market question text
- **condition_id**: Condition ID (hex string)
- **clob_token_ids**: JSON-encoded array string of token IDs

## Normalization Process

The `PolymarketNormalizer` converts raw `OrderBookSummary` records into canonical `MarketQuote` records:

1. **Parse timestamps**: Convert epoch milliseconds string → UTC datetime
2. **Extract top-of-book**: Find best bid (highest price) and best ask (lowest price)
3. **Aggregate sizes**: Sum sizes at each price level (handles potential duplicates)
4. **Construct MarketQuote**: Fill canonical fields with provider metadata

## Top-of-book Semantics

### Best Bid Extraction
- Scan all bid levels in the order book
- **Best bid = highest bid price** across all levels
- Bid size = aggregate size at the best bid price level

### Best Ask Extraction
- Scan all ask levels in the order book
- **Best ask = lowest ask price** across all levels
- Ask size = aggregate size at the best ask price level

### Edge Cases
| Scenario | bid_price | bid_size | ask_price | ask_size |
|----------|-----------|----------|-----------|----------|
| Empty book (no bids, no asks) | None | None | None | None |
| Bids only (no asks) | float | float | None | None |
| Asks only (no bids) | None | None | float | float |
| Multiple levels at same price | float | aggregated | float | aggregated |

## Timestamp Handling

### Source Timestamp
- **Source**: `OrderBookSummary.timestamp` from CLOB API
- **Format**: Epoch milliseconds as string (e.g., `"1782753357257"`)
- **Conversion**: Parsed to UTC datetime with microsecond precision
- **Policy**: Represents when the market event was generated by Polymarket

### Ingestion Timestamp
- **Source**: System clock at normalization time
- **Override**: Injectable `clock` parameter for deterministic tests
- **Policy**: Represents when our system received/recorded the quote

Both timestamps must be UTC, timezone-aware. Naive datetimes are rejected.

## Instrument Identity

- **provider**: `"polymarket"` (canonical identifier)
- **provider_instrument_id**: The `token_id` (asset_id) from the OrderBookSummary
- The `token_id` uniquely identifies an outcome token within Polymarket
- The `condition_id` (market) identifies the market, but is NOT used as the instrument ID

## Error Handling

### NormalizationError
Raised when:
- `token_id` is empty or whitespace-only
- Epoch timestamp string cannot be parsed
- Raw record cannot be parsed as `OrderBookSummary`
- Any required field is missing or malformed

### Client Errors (from PolymarketClient)
- `PolymarketAPIError`: API returned an error response (HTTP 4xx/5xx)
- `PolymarketConnectionError`: Unable to connect to Polymarket API
- `PolymarketTimeoutError`: Request timed out (default 30s)
- `PolymarketClientError`: Other request failures

## Dataset Snapshot Flow

To create a deterministic Dataset from live data:

```python
from datetime import UTC, datetime
from quant_engine.market_data.models import Dataset
from quant_engine.providers.polymarket import PolymarketNormalizer
from quant_engine.providers.polymarket.client import PolymarketClient

client = PolymarketClient()
normalizer = PolymarketNormalizer()

# Fixed timestamp for deterministic record IDs
fixed_ts = datetime(2026, 1, 1, 12, 0, 0, tzinfo=UTC)

# Fetch and normalize multiple tokens
tokens = ["token_id_1", "token_id_2", "token_id_3"]
quotes = []
for token_id in tokens:
    book = client.get_order_book(token_id)
    quote = normalizer.normalize_order_book(
        token_id=token_id,
        order_book=book,
        source_timestamp=fixed_ts,
        ingestion_timestamp=fixed_ts,
    )
    quotes.append(quote)

# Create deterministic dataset
dataset = Dataset(records=quotes)
# dataset.dataset_id is deterministic for same inputs
```

## Limitations

This adapter does NOT support:
- **Order execution** — read-only, no trading capabilities
- **Full order book as canonical data** — only top-of-book is normalized
- **Real-time streaming** — poll-based, not WebSocket
- **Market metadata normalization** — MarketMetadata stays in provider-specific format
- **Historical data** — only current order book snapshots
- **Multi-outcome markets** — treats each token independently
- **Spread/midpoint normalization** — available from client but not normalized to MarketQuote
